# Verified project rules

- Account-switch shutdown must select executable ownership as well as ancestry. A regression fixture representing RunDog launched by Codex was selected by the former all-descendants rule, and inherited package identity also made unrelated executables look like Desktop. `process_model::owned_processes` is now the shared inspection/polling boundary; regression tests cover both paths, orphaned/new helpers, shell intermediates, PID reuse, and a 2,048-case property test. Never pass an unrestricted descendant set to termination.
- Dead-code audits must include test callers and executable reachability: normal Clippy accepts unused public library exports. In #3, compiling private root modules with the production entry point plus the original tests distinguished unused accessors/re-exports from test-only APIs; `SecretBytes::len` was used by the DPAPI test. After cleanup the same test-inclusive compile passed with `-D warnings`. Do not remove the `InstanceGuard` handle merely because its field has `allow(dead_code)`: retaining it owns the named mutex lifetime.
- Windows CLI smoke checks must wait on the actual process. The GUI-subsystem executable returned no `$LASTEXITCODE` when invoked directly from the PowerShell release check; that was missing exit-status evidence, not an application failure. `Start-Process -PassThru -WindowStyle Hidden`, redirected output, and a bounded `WaitForExit` produced exit 0 for the installed `list` command. Keep account-list output private and remove temporary captures after checking the result.
